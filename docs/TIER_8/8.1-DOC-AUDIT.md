# Tier 8.1 — Documentation audit

## Why this matters

Docs rot silently. CLI flags evolve, RFCs land, config formats change —
and the docs sit there saying what was true two minor releases ago. 8.1
is a single deliberate pass to reconcile every doc with the current code.

This work is unglamorous. It is also the prerequisite for trusting any
downstream artifact (8.2 service guides, Tier 7 cert-manager docs,
external blog posts) that references these docs.

## Scope

Every file under `docs/`, plus `README.md` and `CHANGELOG.md`:

| File                                          | Primary audit targets                                                        |
| --------------------------------------------- | ---------------------------------------------------------------------------- |
| `README.md`                                   | Protocol compliance table, CLI flag list, feature inventory, install steps  |
| `CHANGELOG.md`                                | Entries since last release follow `Added/Fixed/Changed/Security/Documentation` |
| `docs/CPS.md`                                 | RFC 3647 §6 structure complete, policy OID matches `--cps-policy-oid` default |
| `docs/THREAT_MODEL.md`                        | Already refreshed in 6.3 — re-verify no new gaps since                      |
| `docs/COMPATIBILITY.md`                       | Client interop matrix matches what 6.2 actually proves green                 |
| `docs/MIGRATION.md`                           | SQLite → Postgres steps still work against current schema                    |
| `docs/PERFORMANCE.md`                         | Numbers from current 6.7 bench run                                           |
| `docs/INTEROP_MATRIX.md` (from 6.2)           | Matches the live CI status                                                   |
| `docs/LICENSES.md` (from 6.4)                 | One row per current dependency                                               |
| `docs/DEPLOYMENT/homelab.md`                  | All flags/paths valid; quickstart works end-to-end                           |
| `docs/DEPLOYMENT/k8s-cert-manager.md`         | cert-manager API version current; manifests apply cleanly                    |
| `docs/DEPLOYMENT/k8s-istio.md`                | Istio version current; example mesh config still applies                     |
| `docs/DEPLOYMENT/offline-root.md`             | `ceremony.py` references match current signature                             |

## Audit checklist (per doc)

Walk this top to bottom for every file in scope:

1. **CLI flags** — every flag mentioned exists in current `python pypki.py
   --help` output. Run a diff between docs and `--help`; both directions
   matter.
2. **Config keys** — every key mentioned matches the actual config-loading
   code in `pki_server.py` / `web_ui.py` / etc.
3. **File references** — every `file.py:NNN` reference still resolves to
   the relevant code (line may have shifted; update the number).
4. **Commands** — every shell command shown runs as written against a
   fresh checkout. No "should work."
5. **Endpoints** — every URL path matches the actual `dispatcher_server.py`
   routing.
6. **RFCs claimed** — every RFC in the README compliance table is actually
   implemented (i.e., has a `TestRFC<nnnn>` class in `test_pki_server.py`).
7. **Screenshots** (where present) — reflect the current Web UI; replace
   if stale.
8. **External links** — still resolve (HTTP 200). Update or remove dead
   links; don't leave 404s.
9. **Mermaid diagrams** (`pypki-flows.html`) — match current protocol
   message sequences.
10. **"Last reviewed" header** — updated to the audit commit date and
    SHA. Format: `> Last reviewed: 2026-MM-DD (commit abc1234)`.

## Process

One doc per session. Don't batch:

1. Open the doc.
2. Walk the checklist top to bottom.
3. **Fix in place.** No parallel "audit notes" document — drift goes
   where the drift lives.
4. Commit with prefix: `docs: 8.1 audit pass — <doc name>`.
5. Update "Last reviewed" header in the same commit.

Findings of code/docs mismatch:
- **Doc wrong, code right** — fix the doc.
- **Code wrong, doc right** — file a bug. Don't silently change the doc
  to match buggy code. The audit doc lists the bug filed.
- **Both wrong** — fix both, in separate commits.

## Drift detection scripting

Some of the checklist can be scripted. Write small helpers under
`scripts/audit/` to make subsequent audits cheap:

- `audit/cli_flag_diff.py` — diff documented flags vs `--help`
- `audit/endpoint_check.py` — scrape URL paths from docs, hit them
- `audit/link_check.py` — HTTP-check external links
- `audit/rfc_table_check.py` — cross-reference README compliance table
  against `TestRFC<nnnn>` test classes

These don't replace the human pass — they catch mechanical drift so the
human pass focuses on semantic accuracy.

## Conventions

- **"Last reviewed" is mandatory after audit.** Even docs that didn't
  change get a new "Last reviewed" date — that's the signal someone
  actually read them.
- **Skipped checklist items get explicit `N/A — <reason>`** rather than
  silent omission. E.g., "N/A — this doc has no screenshots."
- **Audit doesn't add new content.** If a section needs adding (new
  feature undocumented), file that as a separate PR after the audit
  completes. Mixing audit and new content makes review messy.
- **Audit is a fixed budget.** If a doc takes more than two sessions to
  audit, the doc has bigger problems than drift — flag it for rewrite as
  a separate work item.

## Per-change checklist (any doc edit during 8.1)

- [ ] Audit checklist walked top to bottom
- [ ] "Last reviewed" header updated to audit commit date + SHA
- [ ] All commands tested against fresh checkout
- [ ] Code references re-verified (line numbers still resolve)
- [ ] If code change needed, filed separately and linked in PR
- [ ] CHANGELOG `### Documentation` entry

## Success criteria

8.1 is "done" when:

1. Every file in scope has a "Last reviewed" date within the last 30 days
   and a current commit SHA.
2. `audit/cli_flag_diff.py` reports zero drift between docs and `--help`.
3. `audit/endpoint_check.py` reports zero documented endpoints that
   return 404.
4. `audit/rfc_table_check.py` reports zero RFCs claimed in README without
   a matching test class (and zero test classes for RFCs not in the
   compliance table).
5. `audit/link_check.py` reports zero broken external links.
6. Every code-reference (`file.py:NNN`) resolves to a real line.
7. Every shell command in every doc runs successfully against a fresh
   checkout.
