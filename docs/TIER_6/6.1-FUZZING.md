# Tier 6.1 — Fuzz the hand-rolled ASN.1

## Why this is first

PyPKI hand-rolls DER encoding and decoding in several public-facing parsers
because `cryptography` doesn't expose the primitives we need:

- `scep_server.py` — `_seq`, `_set`, `_oid`, `_integer`, `_octet_string`,
  `_ctx`, `_encode_length`, `_decode_tlv` are recursive byte parsers that
  accept anonymous, attacker-controlled input.
- `cmp_server.py` — PKIMessage parsing and CRMF POPO verification are
  similarly hand-rolled.
- `pki_server.py` — ML-DSA TBSCertificate is constructed by hand because
  `cryptography` 48.0.0 doesn't accept ML-DSA public keys in
  `CertificateBuilder` yet.

`test_pki_server.py` exercises happy paths. It does not cover length-prefix
overflows, deeply nested SEQUENCE-of-SEQUENCE bombs, malformed OIDs, integer
sign-bit edge cases, or context-specific tag confusion. Those are exactly the
bugs fuzzing finds.

## Targets (priority order)

| # | Target                                | File              | Surface                  |
| - | ------------------------------------- | ----------------- | ------------------------ |
| 1 | `_decode_tlv` (and recursion partners)| `scep_server.py`  | Primitive parser         |
| 2 | SCEP `pkcsPKIEnvelope` parse          | `scep_server.py`  | Anonymous public POST    |
| 3 | CMP PKIMessage parse                  | `cmp_server.py`   | Anonymous public POST    |
| 4 | CRMF POPO verify                      | `cmp_server.py`   | Authenticated POST       |
| 5 | EST CSR ingest                        | `est_server.py`   | Authenticated POST       |
| 6 | ML-DSA TBSCertificate round-trip      | `pki_server.py`   | Self-constructed; verify |
| 7 | OCSP request parse                    | `ocsp_server.py`  | Anonymous public POST    |
| 8 | TSA TimeStampReq parse                | `tsa_server.py`   | Anonymous public POST    |

## Tooling

**Primary**: Atheris (Google's libFuzzer binding for Python).

Atheris goes in `requirements-dev.txt`. It MUST NOT be imported by any
server module. The fuzz harnesses live in `fuzz/` and import from PyPKI but
are never imported back.

**Fallback** (stdlib-only, for environments where Atheris won't build):
random-walk harness in `fuzz/_stdlib_runner.py` — seeds with the corpus,
applies bit-flip / chunk-splice mutations, runs N iterations. Less effective
than coverage-guided fuzzing but zero new dependencies.

Both runners share the same `TestOneInput(data: bytes) -> None` harness
signature.

## Corpus sourcing

Each harness ships with seed inputs in `fuzz/corpus/<target>/`:

1. **From existing fixtures** — extract DER blobs already produced by
   `test_pki_server.py` happy-path tests.
2. **From real clients** — capture a successful enrolment from sscep,
   openssl cmp, libest, certbot etc. (see 6.2) and check the request bodies
   into the corpus.
3. **Boundary cases** — minimal valid DER, single-byte primitives, max-length
   encodings.

Each corpus entry must be reproducible (document where it came from in
`corpus/README.md`) and small (<4 KiB).

## CI integration

Two modes:

- **Per-PR** — 5-minute wallclock budget per harness. Goal: no crash, no
  hang, no leak. Fast feedback.
- **Nightly** — 1 hour per harness, plus corpus minimization. Crashes get
  filed as issues automatically and the offending input is checked into
  `fuzz/corpus/regressions/`.

Job name: `fuzz` in `.github/workflows/`. Matrix on Python 3.12. Failure on
crash, timeout, or new unique path that doesn't reduce to a known input.

## Per-finding workflow

1. Crash reproducer saved to `fuzz/corpus/regressions/<harness>/<sha256>.der`.
2. Minimized to the smallest input that still triggers (Atheris' built-in
   minimizer or manual).
3. New test added to `test_pki_server.py`, class `TestTier6Fuzz<area>`,
   method `test_<harness>_<sha8>_does_not_crash`.
4. Fix lands in the relevant parser.
5. CHANGELOG: `### Security` (or `### Fixed` if no exploitability).
6. The regression input stays in the corpus forever as a permanent guard.

## Per-change checklist (new parser added to PyPKI)

- [ ] New harness in `fuzz/harness_<name>.py`
- [ ] Seed corpus in `fuzz/corpus/<name>/` (≥ 5 inputs)
- [ ] Added to `.github/workflows/fuzz.yml` matrix
- [ ] `run_tests.sh --fuzz` invokes it
- [ ] First clean 5-minute run documented in PR

## Success criteria

Tier 6.1 is "done" when:

1. Every target above has a harness.
2. Nightly 1-hour runs complete with no new unique paths across two
   consecutive weeks.
3. The regressions corpus has at least one entry per harness (i.e., we found
   and fixed at least one real bug — if we didn't, the harness probably
   isn't exercising the parser).
4. Coverage of each target parser is ≥ 90% line coverage from the corpus
   alone (measured with `coverage.py` running the harness inputs).

## Anti-goals

- Don't fuzz the `cryptography` library's parsers. That's upstream's job.
- Don't fuzz HTTP framing — `http.server` is stdlib and well-tested.
- Don't ship Atheris as a runtime dependency. Dev-only forever.
