### Phase B — Kernel module signing (module.sig_enforce=1)

Module signing chain:
- Private key: EC P-256 generated with `openssl ecparam`
- Cert: `signing_cert.pem` signed by PyPKI CA (`ca/ca.key` + `ca/ca.crt`)
- Cert added to `.secondary_trusted_keys` (which PyPKI Root CA signed → builtin trust chain)
- Tool: `scripts/sign-file sha512 signing_key.pem signing_cert.pem hello.ko`

```
modinfo hello_signed.ko:
  sig_id:         PKCS#7
  signer:         PyPKI Root CA
  sig_hashalgo:   sha512
  signature:      30:45:02:21:00:CB:04:43:F3:...
```

| Gate | Action | Expected | Status | Evidence |
|------|--------|----------|--------|----------|
| B1 | `insmod hello_signed.ko` | loads | **PASS** | `hello: loading out-of-tree module taints kernel.` `hello: loaded (ima-evm-harness test module)` |
| B2 | `insmod hello_unsigned.ko` | EKEYREJECTED | **PASS** | `Loading of unsigned module is rejected` exit 1 |
| B3 | `insmod hello_wrongkey.ko` | EKEYREJECTED | **PASS** | `Loading of module with unavailable key is rejected` exit 1 |
| B4 | `insmod hello_tampered.ko` | sig fail | **PASS** | `Key was rejected by service` exit 1 |

**Key insight**: The `CMS_NOCERTS` flag in `scripts/sign-file` means the cert is NOT
embedded in the PKCS#7 blob. Instead, the PKCS#7 identifies the signer by
`IssuerAndSerialNumber`. For verification to succeed, the kernel must find the signing
cert in a trusted keyring. Adding the leaf cert to `.secondary_trusted_keys` (via
`keyctl padd asymmetric '' %keyring:.secondary_trusted_keys < leaf.der`) completed
the chain: leaf (in secondary) → PyPKI Root CA (in builtin_trusted_keys).
